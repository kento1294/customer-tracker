☀️ 朝（開店前）
1

客層記録アプリを開く

iPadで客層記録アプリを開くと、朝の現金カウントがまだの場合は下のお知らせが自動で出ます。「今すぐ入力する」をタップします。

2

レジの現金を金種ごとに数えて入力

「朝（開店時）」タブが選ばれた状態で開きます。紙幣・硬貨ごとの枚数を入力すると、合計金額が自動で出ます。確認できたら「この金額で記録する」をタップ。

3

Squareで「ドロワーを開始」

Square POSレジアプリで現金管理のドロワーを開始し、手順2の合計金額を入力します。

Square POSレジアプリ（iPad）
  1. 画面下の レポート をタップ
  2. 左のメニューで 現金管理 を選ぶ
  3. 「ドロワー開始時の残高」に ¥37,700（アプリの合計）を入力
  4. ドロワーを開始 をタップ
※現金管理はiPadのみ。iPhoneでは使えません。
※前日の金額は引き継がれないため、毎朝その日の金額を入力してください。

開始すると下の画面に切り替わります。「ドロワー開始時の残高」がアプリの合計金額と同じになっていれば完了です。

表示項目意味
入金/出金営業中に記録した両替・経費などの出し入れの合計
現金売上現金で受け取った会計の合計
現金の払い戻し現金で返金した金額の合計
ドロワー開始時の残高朝に入力した金額
現金残高今レジに入っているはずの金額（開始時の残高＋入金/出金＋現金売上−払い戻し）

「ドロワーの説明」は入力しなくて大丈夫です。

4

客層記録画面に戻って確認

「←戻る」で客層記録画面に戻ると、右上の欄に「💰朝 ✓ ¥37,700」と表示されます。これで朝の作業は完了です。

🛍️ 営業中
5

会計のたびに客層を登録

Squareで会計したら、客層記録アプリで購入場所・年代・来店回数・性別・購入理由・来店理由の6項目をタップし、会計金額（税込）を入力します。ボタンが赤い「登録する」に変わったらタップします。

  • 金額はSquareの会計画面の合計金額をそのまま入力します。金額が空だとボタンが「金額を入力してください」になり登録できません
  • 買わずに帰ったお客様も、購入理由で「購入なし（来店のみ）」を選んで登録します（金額は不要）。日次報告の来客数に使われます
  • ここで登録した内容が、閉店後の日次営業報告に自動で集計されます。登録漏れがあると報告の数字も少なくなります
6

営業中に気をつけること

  • 両替や経費の支払いでレジの現金を出し入れしたときは、Squareで入金/出金を記録する（下の手順参照。記録しないと閉店時の差額の原因になります）
  • 来客数や購入者の内訳を紙で数える必要はありません（客層記録から自動で集計されます）。そのかわり、会計ごと・来店ごとの登録を忘れないようにしてください
  • アプリは開いたままで大丈夫です（10分ごとに自動で状況を確認します）
Squareで入金/出金を記録する（iPad）
  1. 画面下の レポート → 左のメニューの 現金管理 → 入金/出金
  2. 「金額」に出し入れした金額を入力
  3. 「説明」に理由を入力（例：両替、備品購入、釣銭補充）
  4. レジにお金を入れたときは 入金、レジからお金を出したときは 出金 をタップ
記録した内容は下の「入金/出金の合計」に反映されます。終わったら左上の✕で閉じます。
🌙 閉店後（19:00〜）
7

晩のお知らせから現金カウントへ

19:00を過ぎると、晩の現金カウントがまだの場合に下のお知らせが出ます（出ない場合はヘッダーの💰から開いてもOK）。「今すぐ入力する」をタップ。

8

レジの現金を数えて記録（晩タブ）

「晩（閉店時）」タブが選ばれた状態で開きます。朝と同じように金種ごとの枚数を入力し、「この金額で記録する」をタップします。

9

Squareで「ドロワーを終了」（レジ締め）

Square POSレジアプリ（iPad）
  1. 画面下の レポート → 左のメニューの 現金管理 → ドロワーを終了
  2. 「実際の現金残高」に手順8の合計金額を入力
  3. 入力欄のすぐ下の「予定金額」と同じ金額か確認
  4. 差額がある場合は、「説明」に理由を入力（わかる範囲で）
  5. 下の ドロワーを終了 をタップ
差額が出たときは、まず入金/出金の記録漏れと数え間違いがないか確認してください。「予定金額」は手順3の画面の「現金残高」と同じ金額です。
10

Squareで「ドロワーを締める」（その日の確定）

ドロワーを終了しただけでは、まだ「終了済のドロワー」として残っています。最後に締めまで行うと、その日の現金管理が確定し、設定したメールアドレスに現金レポートがメールで届きます。

Square POSレジアプリ（iPad）
  1. 画面下の レポート → 左のメニューの 現金管理履歴
  2. 「終了済のドロワー」に表示されている当日のドロワーをタップ
  3. 内容を確認して締めるボタンをタップ
  4. 当日のドロワーが「締め済のドロワー」の欄に移れば完了
「終了済のドロワー」が「終了したドロワーはありません」になっていれば、締め忘れはありません。
2026/09/27より前の記録を見るときは、パソコンのSquareデータ（管理画面）の［レポート］から確認します。
11

📊 日次営業報告を入力

ヘッダーの📊をタップ。日付が本日になっていることを確認します。開くと、その日の客層記録（店頭）が自動で集計され、青い欄に数字が入った状態になります。

  1. 当日売上をSquareのレポート ＞ 売上の金額と見比べる（違う場合は、客層記録の登録漏れや金額の打ち間違いがないか確認し、正しい金額に直す）
  2. 青い欄の数字に違和感があれば手で修正する（直した欄は白に戻ります）
  3. 紫の事業カテゴリ別の5項目は自動では入らないので、今まで通り手入力する
  4. 「この内容で記録する」をタップ

「金額が入っていない会計が○件あります」と出たときは、客層記録に金額の入力漏れがあります。当日売上などが少なく出ているので注意してください。

12

最後に確認して終了

客層記録画面の右上が「💰朝 ✓」「💰晩 ✓」の両方になっていて、Squareの現金管理履歴で当日分が「締め済のドロワー」に入っていれば、1日の作業は完了です。

📋 客層記録の使い方

  1. お客様の購入場所・年代・来店回数・性別・購入理由・来店理由を、それぞれタップして選択
  2. 会計金額（税込）を入力。買わずに帰ったお客様は、購入理由で「購入なし（来店のみ）」を選ぶ（金額は不要）
  3. 必要であればメモ欄に補足を入力
  4. 全6項目と金額がそろうと「登録する」ボタンが赤く有効化される
  5. タップして登録。画面下部（iPadは右側）の「記録履歴」にその場で反映される

誤って登録した場合は、履歴の「✕」を2回タップ（1回目で「確定」に変わる）すると取り消せます。

💰 現金カウントの使い方

基本の流れ

  1. ヘッダーの💰アイコンをタップ
  2. 「朝（開店時）」「晩（閉店時）」のタブを選択
  3. 紙幣・硬貨ごとの枚数を入力すると、自動で合計金額が計算される
  4. 「この金額で記録する」をタップ
  5. 表示された合計金額を、Squareのレジアプリの「現金管理」機能に手入力する
⚠️ この画面での記録は「金額の集計・記録用」であり、Squareへの反映は別途手入力が必要です。

リマインダーについて

  • 朝：客層記録アプリを開いた時点で、その日の朝カウントが未入力なら自動でポップアップ表示
  • 晩：19:00以降、その日の晩カウントが未入力なら自動でポップアップ表示（10分ごとに再チェックされます）
  • 「あとで」を押すと閉じられますが、条件を満たす限り再度表示されます

すでに記録済みの日を開いた場合

画面上部にオレンジ色のバナーで「⚠️すでに¥◯◯で記録済みです」と表示されます。そのまま再送信すると上書きされるのでご注意ください。

📊 日次営業報告の使い方

  1. ヘッダーの📊アイコンをタップ
  2. 上部の日付が本日になっていることを確認（前日分をあとから入力する場合は日付を変更）
  3. 客層記録から自動で入った青い欄を確認・修正し、事業カテゴリ別の5項目を手入力。人数欄には「人」、金額欄には「円」の単位が表示されます
  4. 「この内容で記録する」をタップ

その日にすでに記録がある場合は、記録済みの数値が表示され、上部に警告バナーが出ます（自動集計で入れ直すときは「🔄 客層記録から集計して入力し直す」をタップ）。項目ごとの意味は「日次報告 項目説明」タブを参照してください。

🗓️ シートの自動生成ルール

  • シート名は自動で「【原本】yyyy年mm月営業報告」の形式で作成される
  • 日曜・月曜（定休日）は行全体が灰色でハイライトされる
  • D列（営業残日数）は定休日を除いた営業日ベースで自動計算される
  • 月末の下2行に、月間合計（売上・一般・来客数・購入人数など）が自動集計される
共通ボタン（💰📊）が表示されない

ファイルの中身自体は正しいのに表示されない場合、多くはキャッシュが原因です。以下を順番に試してください。

  1. ページを完全に再読み込み（ブラウザの更新ボタン長押し→「キャッシュの消去とハード再読み込み」）
  2. URLの末尾に ?v=2 のようなダミーの文字を付けて開き直す
  3. それでも直らない場合、VPNやセキュリティプロキシを一時的にオフにして確認
  4. ホーム画面に追加したアイコンから開いている場合、一度アイコンを消して開き直す

数分〜数十分で自然に直ることもあります（GitHub Pages側のキャッシュ反映待ち）。

共通ページを開いてもデータが送信されない・反映されない

GAS（Google Apps Script）のコードを修正した後、以下を忘れていないか確認してください。

「デプロイ」→「デプロイを管理」→✏️→バージョンを「新バージョン」に変更→デプロイ

これを行わないと、コードを直しても実際の動作には反映されません。

現金カウント「今すぐ入力する」を押すと404エラーが出る

該当ファイル（cash-count.html）がリポジトリにアップロードされていないか、ファイル名が間違っている可能性が高いです。

ブラウザで直接以下を開いて確認してください。

https://kento1294.github.io/customer-tracker/cash-count.html

ここで404が出る場合は、ファイル名の大文字・小文字も含めて再確認し、正しい名前で再アップロードしてください。

現金カウント記録したのに「未入力」のリマインダーが消えない

スプレッドシートに書き込みは成功しているのに、チェック処理側の型判定でうまく認識できていないケースがあります。GASの以下URLを直接開いて、レスポンスを確認してください。

GAS_URL?action=checkTodayCashCountStatus&callback=test

morningやeveningがfalseのままなら、スプレッドシート「現金カウント」シートのA列（タイムスタンプ）が正しい日付形式で保存されているか確認してください。

日次報告「シートが見つかりません：undefined年undefined月」と出る

GASエディタの「実行」ボタンは、引数（年・月）を渡さずに関数を実行してしまうため発生します。

直接regenerateReportSheetFormattingを実行するのではなく、対象月ごとに用意されたラッパー関数（例：runRegenerateAugust2026）を選んで実行してください。

日次報告入力した数値が違う日・違う列に入ってしまう

まず、画面上部の日付が正しいかを確認してください。日付を基準に「年月からシート名」「日にちから行番号」が自動計算される仕組みのため、日付がずれているとそのまま違う行に書き込まれます。

日次報告自動入力の当日売上がSquareの売上と合わない

当日売上は「客層記録に入力された会計金額の合計（店頭のみ）」です。次のどれかが原因のことが多いです。

  • 客層記録の登録漏れ（会計したのに登録していない）
  • 金額の打ち間違い・入力漏れ（「金額が入っていない会計が○件あります」と表示される）
  • 購入場所を「マルシェ」「その他」で登録した会計がある（店頭以外は集計されません）
  • 返品・払い戻しがあった（客層記録には反映されません）

原因がわかれば、日次報告の画面で正しい金額に直してから記録してください。登録漏れの会計を客層記録にあとから登録し、「🔄 客層記録から集計して入力し直す」を押す方法もあります。

日次報告日次報告を開いても自動入力されない
  • 「この日の客層記録（店頭）はまだありません」と出る場合：その日の店頭の客層記録が1件もありません。日付が正しいか確認してください
  • 「この日はすでに記録済みのため…」と出る場合：記録済みの数値を表示しています。集計し直すときは「🔄 客層記録から集計して入力し直す」をタップ
  • 「集計に失敗しました」と出る場合：GASの再デプロイ（新バージョン）がされているか確認してください。手入力で記録することはできます
共通客層記録の送信でエラーが出る（送信エラー表示）

通信タイムアウト（10秒）または回線状況が主な原因です。データ自体は「ローカル保存済み」として履歴に残るため消えることはありませんが、実際にスプレッドシートに反映されたかは、時間を置いてから同じ内容がシートにあるか確認してください。

🛠️ 初回だけ必要な設定（Square）

現金管理はSquareの初期状態では使えないため、アドオンとして追加が必要です（無料）。

  1. iPadのSquare POSレジアプリで ≡ その他 → 設定 → アドオン の「＋」
  2. 「現金管理」→「無料で追加」
  3. 追加後は、画面下の レポート の左メニューに「現金管理」「現金管理履歴」が表示される
  4. 締めのときに現金レポートをメールで受け取るには、現金管理の設定でメール送信とメールアドレスを設定しておく

アプリから追加した場合、その端末だけで有効になります。端末を増やしたときは、その端末でも追加してください。

⚙️ 修正時の基本フロー

  1. 該当ファイル（.htmlまたは.gs）を編集
  2. .gsファイルを直した場合：「デプロイ」→「デプロイを管理」→✏️→「新バージョン」→デプロイ
  3. .htmlファイルを直した場合：GitHubリポジトリに上書きアップロード（コミット）
  4. 反映確認（うまく反映されない場合は「トラブルシューティング」タブを参照）

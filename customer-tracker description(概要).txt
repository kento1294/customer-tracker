# customer-tracker.html 解説ドキュメント

## 概要

客層記録Webアプリの全コードを1ファイル（HTML/CSS/JavaScript）に収めたスタンドアロンアプリケーション。
外部ライブラリやフレームワークへの依存はゼロ。
iPad mini（横画面）とiPhone 16（縦画面）の両方に対応するレスポンシブデザイン。
GitHub Pagesでホスティングし、Safari上でPWAとして動作する。
登録結果は以下スプシに出力
https://docs.google.com/spreadsheets/d/1aIKUJ_4uIb_qzcqzEgBhshHLdXF747-F-iJYjBHxf-4/edit?gid=257499334#gid=257499334

【2026年8月追記】
レジ現金管理ワークフロー（金種別現金カウント）を追加統合。
客層記録アプリ（index.html）に、朝・晩の現金カウント状況の確認・リマインダー機能を組み込み、
カウント専用ページ（cash-count.html）と連携する構成になった。詳細は「7. 現金カウント機能」を参照。

## ファイル構成

現在、リポジトリ（kento1294/customer-tracker）には以下のファイルが存在する。

```
customer-tracker/
├── index.html                          ... 客層記録アプリ本体（+現金カウントの状況表示・リマインダー）
├── cash-count.html                     ... 金種別現金カウント入力ページ（新規）
└── （GASプロジェクト側・リポジトリ外）

    └── gas-cash-count-functions.gs      ... 現金カウント関連の処理（新規ファイルとして追加）
```

index.html自体の内部構成は以下の3ブロック。

```
index.html
├── <head>     ... メタ情報・CSS
├── <body>     ... HTML構造
└── <script>   ... JavaScript（ロジック全体）
```

## 4. JavaScript

### 定数・設定

#### GAS_URL
```javascript
const GAS_URL = "https://script.google.com/macros/s/AKfycby.../exec";
```
Google Apps ScriptのデプロイURL。客層データ・現金カウントデータ双方の送信先（共通）。

#### CATEGORIES
カテゴリを定義する配列。各オブジェクトの構造:

| プロパティ | 型 | 説明 |
|-----------|-----|------|
| `id` | string | 内部識別子（GASのパラメータ名と一致） |
| `label` | string | 画面表示名 |
| `color` | string | カテゴリのメインカラー（選択時のボタン色） |
| `colorLight` | string | 未選択時のボタン背景色 |
| `options` | string[] | 選択肢の一覧 |
| `cols` | number | iPad表示時のグリッド列数 |
| `mobileCols` | number | iPhone表示時のグリッド列数 |

#### EVENING_REMINDER_HOUR（新規）
```javascript
const EVENING_REMINDER_HOUR = 19;
```
この時刻（端末のローカル時間、JST想定）以降、晩の現金カウントが未記録の場合にリマインダーモーダルを表示する。

#### グローバル変数

| 変数 | 型 | 説明 |
|------|-----|------|
| `selections` | object | 現在の選択状態 `{ age: "30代", gender: "男性", ... }` |
| `history` | array | 登録履歴（最大30件、新しい順） |
| `confirmingDelete` | number/null | 削除確認中の履歴インデックス |
| `confirmTimer` | number/null | 削除確認の自動キャンセル用タイマーID |
| `sending` | boolean | GAS送信中フラグ（二重送信防止） |

### 関数一覧

#### 初期化系

| 関数 | 説明 |
|------|------|
| `isMobile()` | 画面幅700px未満ならtrue |
| `init()` | 起動時にカテゴリカードを生成し、resizeイベントを登録 |
| `applyCols()` | 画面幅に応じてグリッド列数を切り替え |
| `buildCatCard(cat)` | カテゴリカードのDOM要素を動的生成。ラベル＋選択肢ボタンを構築 |

#### 選択操作系

| 関数 | 説明 |
|------|------|
| `handleSelect(catId, option)` | 選択肢をタップした時の処理。トグル動作（再タップで解除） |
| `resetAll()` | 全選択とメモをクリア |
| `updateUI()` | 選択状態をDOMに反映。進捗バッジ、ボタン色、登録ボタンのテキストを更新。iPad用・iPhone用の両方の登録ボタンを同期 |

#### 送信系（客層記録）

| 関数 | 説明 |
|------|------|
| `handleSubmit()` | 登録ボタン押下時の処理。バリデーション→楽観的UI更新→GAS送信→結果反映 |
| `sendToGAS(data)` | JSONP方式でGASにデータ送信。scriptタグを動的挿入し、callbackで結果を受け取る。タイムアウト10秒 |

##### sendToGAS の通信フロー
```
1. URLSearchParamsでデータをクエリ文字列に変換
2. ユニークなcallback関数名を生成（_gasCb_タイムスタンプ）
3. window[callbackName]にレスポンス処理関数を登録
4. <script src="GAS_URL?params&callback=callbackName">をDOMに挿入
5. GASがJSONPレスポンスを返す → callback関数が実行される
6. 成功/失敗に応じてPromiseをresolve/reject
7. scriptタグとcallback関数をクリーンアップ
```

#### 現金カウント連携系（新規）

| 関数 | 説明 |
|------|------|
| `formatYen(n)` | 数値を「¥12,340」形式の文字列に変換 |
| `renderCashStatus(morning, evening)` | 取得した朝・晩の記録状況を`#cashStatusCard`に反映。記録済みは緑文字＋金額＋時刻、未記録は「未入力」表示 |
| `checkCashStatus()` | GASの`checkTodayCashCountStatus`をJSONPで呼び出し、ステータスカードを更新。朝が未記録なら朝モーダル、朝は記録済みだが晩が未記録かつ`EVENING_REMINDER_HOUR`以降なら晩モーダルを表示 |

呼び出しタイミング:
- ページ読み込み時（`init()`直後）に1回実行
- `setInterval(checkCashStatus, 10 * 60 * 1000)` により**10分ごとに自動再チェック**（アプリを開きっぱなしでも閉店時刻の見落としに気づけるようにするため）

モーダル操作:
- `#cashModalLater` / `#cashEveningModalLater` … 「あとで」。モーダルを閉じるのみ（次回チェック時に再表示され得る）
- `#cashModalGo` … `cash-count.html?session=morning`へ遷移
- `#cashEveningModalGo` … `cash-count.html?session=evening`へ遷移

#### 履歴系

| 関数 | 説明 |
|------|------|
| `renderHistory()` | 履歴一覧をHTMLとして再描画。ステータスアイコン・カテゴリタグ・メモ・削除ボタンを含む |
| `handleDelete(index)` | 2段階削除。1回目で「確定」表示、3秒以内に再タップで削除実行。3秒経過で自動キャンセル |

#### 通知系

| 関数 | 説明 |
|------|------|
| `showToast(msg, type)` | 画面上部にトースト通知を表示。typeに応じて色が変化（success=緑、warn=黄、error=赤）。2.5秒後に自動消去 |

### ステータスアイコン（客層記録の履歴表示）

| アイコン | syncStatus | 意味 |
|----------|-----------|------|
| ☁️ | `synced` | Spreadsheetへの書き込み成功 |
| ⏳ | `sending` | 送信中 |
| ⚠️ | `error` | 送信失敗（ローカルのみ保存） |
| 📱 | `local` | GAS未設定時のローカル保存 |

## 6. カスタマイズガイド

### 選択肢を追加・変更する場合

CATEGORIESの該当カテゴリのoptionsを編集する。
例: 年代に「70代〜」を追加する場合:

```javascript
options: ["〜10代","20代","30代","40代","50代","60代〜","70代〜"], cols: 7, mobileCols: 4
```

注意: GAS側の変更は不要。送信時にoptionの文字列がそのままパラメータとして送られる。

### カテゴリを追加する場合

1. CATEGORIESに新しいオブジェクトを追加
2. GAS側のdoGet/doPostのappendRowに対応する列を追加
3. Spreadsheetのヘッダー行に新しい列名を追加

### GAS URLを変更する場合

GAS_URL定数を書き換える（index.html・cash-count.html双方）。

### 色を変更する場合

各カテゴリのcolorとcolorLightを変更する。
colorは選択時のボタン色、colorLightは未選択時の背景色。

### 晩リマインダーの時刻を変更する場合

index.html内の`EVENING_REMINDER_HOUR`定数を変更する。

## 7. 現金カウント機能（新規セクション）

### 目的

Squareの「現金管理」機能では紙幣・硬貨ごとの枚数記録ができないため、
金種別カウント→合計金額算出→その金額をSquareに手入力、という運用を補助する目的で追加。
あわせて、朝・晩のカウント入力忘れを防ぐリマインダーと、当日の記録状況の可視化を行う。

### 構成ファイル

| ファイル | 役割 |
|---------|------|
| `cash-count.html` | 金種別（¥10,000〜¥1）の枚数を入力し、自動で合計金額を算出。朝/晩をトグルで切替。JSONPでGASへ送信 |
| `index.html`（追加部分） | 💰導線ボタン、現金カウント状況カード、朝/晩リマインダーモーダル |
| GAS `gas-cash-count-functions.gs` | `recordCashCount`（記録）・`checkTodayCashCountStatus`（当日状況取得）を提供 |
| GAS `コード.gs`の`doGet` | `action`パラメータで客層記録と現金カウントの処理を振り分け |

### データの保存先

「現金カウント」シート（既存の「客層記録」シートとは別。GASが自動作成）

| 列 | 内容 |
|----|------|
| A | タイムスタンプ |
| B | 区分（`morning` / `evening`） |
| C | 合計金額 |
| D | 金種内訳（JSON文字列、例: `{"10000":5,"5000":2,...}`） |

同じ日・同じ区分で複数回記録した場合、行は追記され続けるが、
状況確認時（`checkTodayCashCountStatus`）は**その日・その区分の最後の記録**が採用される。

### cash-count.html の主な仕様

- 金種：¥10,000, ¥5,000, ¥1,000, ¥500, ¥100, ¥50, ¥10, ¥5, ¥1（¥2,000は対象外）
- 枚数入力ごとに合計金額をリアルタイム計算
- 朝/晩トグル：URLクエリ`?session=morning`または`?session=evening`で初期選択を指定可能（index.htmlのモーダルからの遷移時に使用）
- ページ読み込み時、その日・そのセッションに既存の記録があれば、ヘッダー直下に警告バナーで金額・時刻を表示（再入力時の上書き注意喚起）
- 送信ボタン押下でGASの`recordCashCount`をJSONP送信。成功時はバナーを即時更新

### index.html側の現金カウント関連UI

- **💰導線ボタン**：ヘッダーに常設。いつでも`cash-count.html`へ遷移可能（主に晩の入力用）
- **現金カウント状況カード**：送信ボタン直下に常設。当日の朝・晩それぞれの記録有無・金額・時刻を表示
- **朝リマインダーモーダル**：ページ読み込み時、朝が未記録なら表示
- **晩リマインダーモーダル**：`EVENING_REMINDER_HOUR`（現状19時）以降、晩が未記録なら表示。10分ごとの自動再チェックにより、アプリを開きっぱなしでも表示される

### GAS `doGet` の分岐ロジック

```javascript
function doGet(e) {
  const action = e.parameter.action;
  if (action === "recordCashCount") {
    return handleRecordCashCount(e);
  }
  if (action === "checkTodayCashCountStatus") {
    return handleCheckTodayCashCountStatus(e);
  }
  // ...既存の客層記録処理（actionパラメータなしの場合はここに到達）...
}
```
客層記録アプリ側の送信リクエストには`action`パラメータが含まれないため、
既存処理には一切影響を与えない設計になっている。

### 今後の拡張予定（未実装）

  GAS側の金種カウント合計と突合。差異がある場合のみ日次営業報告メールにアラートを追加
  （入力ミス検出・現金過不足検出の両方を想定）
- Square Cash Drawer Shifts APIは読み取り専用のため、Squareへの金額入力自体は今後も手動で行う運用が前提
